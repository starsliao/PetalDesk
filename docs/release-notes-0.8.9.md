## 主要更新

- 新增 Windows「网络检测」小工具，提供 Ping、TCP 端口和 UDP 端口三种探测，都会给出逐次延时以及最小/平均/最大/抖动/丢包统计。
- Ping 使用系统的 `IcmpSendEcho` 接口而不是原始套接字，因此**不需要管理员权限**，普通用户直接可用。
- TCP 端口检测走完整握手，能区分「端口开放」「对端明确拒绝（端口关闭）」和「超时无响应（可能被防火墙丢弃）」三种情况，并给出握手耗时。

## UDP 为什么不给「通/不通」

UDP 没有握手，发出探测后没有回应，既可能是端口开着但服务不回包，也可能是被防火墙静默丢弃 —— 这两种情况在协议层面无法区分。把它笼统报成「不通」会误导排障方向，因此飞花明确区分三种结论：

- **有应答**：收到应用层回包，端口确定开放，并给出延时。
- **端口关闭**：收到 ICMP 端口不可达，端口确定关闭。Windows 会把它作为错误交付给已连接的 UDP 套接字，因此这是一个确定结论。
- **开放或被过滤**：超时且没有任何回应，无法确定。界面用中性的警告色呈现，不会显示成失败。

对 DNS（53）和 NTP（123）会发送真正的协议请求，收到应答即可把结论从「无法确定」提升为「确定开放」；其余端口只能发空载荷，界面会直接说明这一点，避免把超时读成「不通」。

## 兼容

- 本次没有改变密码或 MFA 保险库格式、恢复密码、数据存储路径或跨设备恢复规则。
- 网络检测的 Ping 目前仅支持 IPv4 目标；IPv6 可以使用 TCP 或 UDP 检测。
- 网络检测为 Windows 独有，macOS 当前版本不提供。

## 验证

- 判定与统计逻辑是与平台无关的纯函数，覆盖延时统计、丢包率、请求参数钳制、DNS 与 NTP 探测报文格式，以及三条关键判定：静默的 UDP 只能得出「开放或被过滤」而非「不可达」；同样的静默对 TCP 与 ICMP 可以判定为不可达；收到 ICMP 端口不可达这类确定结论必须压过「测不准」。
- 另有一个默认跳过的实机冒烟用例，验证 `IcmpSendEcho`、TCP 握手计时与 UDP 三态判定在真实网络上确实可用。
- 前端覆盖端口字段随探测方式显隐、参数正确传递、结论与逐次结果渲染、缺少端口时拒绝探测，以及失败时展示原因；并专门断言静默的 UDP 结果呈现为中性警告而不是失败色。
